エージェントモードの GitHub Copilot は、コードベースの調査、変更の提案やファイルの編集、コマンドの実行を自律的に行います。VS Code の Copilot Chat では、ツールの呼び出しやファイル編集をリアルタイムで確認できます。差分を確認し、変更を個別に採用または取り消し、エディターを離れずに追加のプロンプトで会話を調整できます。

この演習では、次の内容を学びます。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして採用します。
- セッションの途中でライトモードの切り替えも追加するようエージェントを導きます。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントが、ハイコントラストモードを実装しています。作業中、デザインチームから「既定のテーマが暗すぎると感じるユーザー向けに、ライトモードも追加してほしい」という要望が届きました。新しい会話を始めるのではなく、既存のセッションを導いて機能を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが調べたファイル、実行したコマンド、提案した編集などの各手順が表示されます。ファイル編集は差分と **Keep** / **Undo** の操作付きでチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの呼び出しを確認します。ファイルの読み込みや編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイルを編集すると、差分がチャットに表示されます。
   - **Keep** を選択すると変更を採用します。
   - **Undo** を選択すると変更を取り消し、エージェントに再度作業させます。
4. チャット上部の **Files changed** を開くと、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ツールの呼び出しで許可が必要な場合 (例: ターミナルコマンドの実行)、エージェントは一時停止して **Allow** を表示します。実行してもよいコマンドだけを許可してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。最後に、変更内容の概要が表示されます。

## ライトモードを追加するようエージェントを導く

ハイコントラストモードができたら、同じ会話でライトモードの切り替えを追加します。エージェントは前の作業、変更したコンポーネント、スタイルの方針、local storage の使い方などのコンテキストを保持しています。

1. Copilot Chat の入力欄に次の追加プロンプトを送ります。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントはすでに行った変更を調べ、ライトモードの追加を提案します。
3. ハイコントラストと同様に、新しい編集を確認して、個別に **Keep** または **Undo** を選びます。
4. エージェントの方針が希望と異なる場合 (例: 切り替え UI を意図せずリファクタリングする場合) は、チャット入力欄の横にある **Stop** で停止し、追加の説明を送ります。

> [!TIP]
> セッションの途中で方向を調整すると、最初からやり直すより早く進められます。追加のプロンプトで変更を依頼できます (例: 「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う」)、方針を修正できます (例: 「3 つ目の切り替えを追加せず、既存の設定パネルにライトモードを統合する」)、範囲を広げることもできます (例: 「両方の切り替えにキーボードショートカットも追加する」)。

## 変更されたファイルをレビューする

コミットする前に、エージェントが変更したファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. いくつかのファイルを開いて差分を確認します。ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保持など、アクセシビリティのパターンを確認します。
4. 内容に問題がなければ **Source Control** パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードで作業中のセッションを監視し、各ファイル編集を確認して採用または却下し、コンテキストを保ったまま追加のプロンプトで作業を拡張しました。

この演習では、次の内容を学びました。

- エージェントの作業をリアルタイムで監視する方法。
- 個々のファイル編集を採用または却下する方法。
- 追加のプロンプトでセッションの進行を調整する方法。
